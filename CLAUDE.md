## Development workflow (superpowers)

Every feature, bugfix, or update follows this chain. **No implementation code
before the plan is presented and approved.**

1. **Bug reports first go through `superpowers:systematic-debugging`** —
   reproduce, isolate, root-cause — then continue the chain from step 3
   (skip brainstorming for small, well-understood fixes).
2. `superpowers:brainstorming` — refine the idea through questions, explore
   alternatives, present design in sections for validation. Save design to
   `.claude/superpowers/YYYY-MM-DD-<topic>/design.md`.
3. `superpowers:writing-plans` — from the approved design, break work into
   bite-sized tasks (2–5 min each) with exact file paths, complete code, and
   verification steps. Save to the same folder as `plan.md`. **Stop here:
   present the plan and wait for explicit approval before any
   implementation.**
4. `superpowers:subagent-driven-development` (default) or
   `superpowers:executing-plans` — fresh subagent per task with two-stage
   review, or batch execution with human checkpoints.
5. `superpowers:test-driven-development` — RED-GREEN-REFACTOR during
   implementation.
6. `superpowers:requesting-code-review` — between tasks, review against the
   plan, report issues by severity; critical issues block progress.
7. `superpowers:verification-before-completion` — before claiming anything
   done: run `php artisan test` and `vendor/bin/pint --test` and confirm
   output.

The user commits and merges manually — do not commit or push unless
explicitly asked.

### Workspace layout

- `.claude/superpowers/YYYY-MM-DD-<topic>/` — one folder per piece of work
  (`design.md`, `plan.md`). Gitignored.
- `.claude/dump/` — scratch/prompt files, generated reports. Gitignored.
